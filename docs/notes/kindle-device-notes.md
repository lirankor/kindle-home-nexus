# Kindle 4 device notes (from the Mac-side agent memory, moved into the repo 2026-10-15)

Chronological working notes kept by the agent that built the panel from the Mac. Facts first, then a dated timeline. The root password is derived from the device serial with the KindleTool rule and is deliberately not written here (public repo); SSH uses the Mac's `id_ed25519` key.

Kindle 4 non-touch (black 2012, FW 4.1.4) set up 2026-10-06 as a home-control panel.

- **Access**: jailbroken (NiLuJe K4 JB) + USBNetwork 0.57 with `auto` at boot. SSH as root with the Mac's `id_ed25519` key. `ssh kindle-wifi` = 192.168.1.139 (LAN), `ssh kindle` = 192.168.15.244 over USB (Mac side en8 must be 192.168.15.201). MKK + KUAL also installed.
- **Architecture**: Kindle can't run a browser. The React app in `github.com/lirankor/kindle-home-nexus` (branch `kindle-bridge`, local clone `~/kindle-ha/kindle-home-nexus`) runs in Docker on pop-os (`~/kindle-home-nexus`, `docker compose up -d --build`) with a `bridge/` service (headless Chromium + sharp): `GET /screen.png`, `GET /key/<name>`, `/healthz` on port 8790. Bridge shares the app's network namespace so Chromium loads 127.0.0.1 (plain hostname `app` got HTTPS-upgraded → ERR_SSL_PROTOCOL_ERROR).
- **Kindle client**: `/mnt/us/nexus/nexus.sh` (repo `kindle/`), stock `/bin/sh` only (busybox 1.7.2: no `read -t`, no `od`; `hexdump -e` segfaults on pipes and on empty `""` formats, works on files with `1/4 "%u " 1/4 "%u " 1/2 "%u " 1/2 "%u " 1/4 "%u\n"`; the usbnet busybox 1.34 lacks sleep/nohup/hexdump, avoid it). Stops the reader framework, readers `dd bs=16 count=1 of=file` + hexdump feed a FIFO, a poller injects `poll` lines, main loop `while read … done < FIFO`, draws with `eips -g`. Cron line in `/etc/crontab/root` keeps it running; `DISABLED` marker stops autostart.
- **Button codes**: 5-way 103 up/108 down/105 left/106 right/194 select; side buttons 193+191 upper (prev tab), 104+109 lower (next tab); 158 Back, 139 Menu, 102 Home, 29 keyboard key.
- **Gotchas**: `Kindle aktualisieren` stays grey but a plain restart installs a `Update_*.bin` left in the root. `~usbNetwork` typed in the search box did not take; the `usbnet/auto` file did. `K3_WIFI_SSHD_ONLY=true` disables USB networking entirely. macOS scp needs `-O` for dropbear. Kindle `wget` has no `-T`; `grep` has no `-E/-x/-w`.
- **Network**: Docker-published ports bypass ufw on pop-os (bridge reachable from LAN without a rule; bound to 192.168.1.15:8790 + 127.0.0.1, auth via BRIDGE_TOKEN in pop-os `.env` and Kindle config, token file the pop-os `.env`). BUT containers cannot reach host-networked HA on 8123 (ufw INPUT): stack subnet pinned to 10.90.90.0/24, needs `sudo ufw allow from 10.90.90.0/24 to any port 8123 proto tcp` (user runs it). Immich works via 100.125.35.82:2283 (published port). Kindle `BRIDGE_URL=http://192.168.1.15:8790`. HA token + Immich API key stored only in `~/kindle-home-nexus/.env` on pop-os (chmod 600, git-ignored); 1 Immich favorite so far. Branch pushed 2026-10-07; pop-os `~/kindle-home-nexus` is a git clone of `kindle-bridge` (`.env` kept there): redeploy = `ssh homeserver "cd ~/kindle-home-nexus && git pull && docker compose up -d --build"`. Verified end-to-end 2026-10-07: buttons drive UI, HA live data shown. User now iterating on the UI (Lovable syncs `main` only).
