- `Seek` fails with UPnP error 710 for REL_TIME, ABS_TIME, X_DLNA_REL_BYTE, REL_COUNT; only TRACK_NR 1 answers OK (no-op). SCPD lists TRACK_NR + REL_TIME, but REL_TIME is refused at runtime. - Remote transport keys do nothing in this mode (user-confirmed). No API on the amp reports key presses (YNCA/UPnP are state-only; a key that changes no state produces no event).

**Why the code behaves as it does**
- Pause = `avTransport.stop()` (UPnP Pause → 501 on this amp), queue status "paused" with offsetMs kept.
- Resume = `pushTrack(track, next, offsetMs)` → SetAVTransportURI + Play + `Seek` (silently caught) → amp starts at 0:00; `decideVerify` (every 6 s) then adopts the amp's position ("resync").

**Options discussed (user chose "do nothing" for now)**
1. Honest pause (minutes): on resume, set offsetMs 0 immediately (no 6 s mismatch); amp display stays "No Content" while paused. Remote stays volume/input only.
2. True resume via relay (hours): server endpoint `/stream/<id>?from=<ms>` piping Jellyfin's transcoder (`startTimeTicks`, key stays server-side); needs a LAN-reachable app/stream port (compose only publishes bridge 8790). Remote still useless.
3. Pull mode (days): enable Jellyfin DLNA server (or MiniDLNA), amp plays natively from it, panel drives it via YNCA (`<SERVER><List_Control>`, Play_Control). Remote skip/pause work, amp display correct, real pause. Loses our queue/mixes/search/gapless unless rebuilt on the amp's slow list browser. Prototype on a branch first.
4. **Intercept the IR remote** (≈€10, the user's preferred direction if any): ESP32 + TSOP38238 (IR receiver) with ESPHome `remote_receiver` near the amp; Yamaha remotes use NEC codes; `on_nec` → `homeassistant.event` (e.g. `esphome.yamaha_ir` with address/command). Panel server subscribes to HA websocket events (`subscribe_events`) using the existing HA_TOKEN (no new port) and maps codes → `queueCommand("next"|"prev"|"toggle")`. The amp still receives the IR but ignores transport keys in this mode, so no double action; volume/input/power keys keep working on the amp and are ignored by us. Pause remains stop+restart unless combined with option 2. Need: user's available boards; learn the key codes first (ESPHome `dump: nec` log).
