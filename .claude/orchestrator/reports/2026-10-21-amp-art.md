# Amp view: 380 px album art (2026-10-21)

Commit fc9a1f4 on media-platform, deployed (server checkout clean). Screenshot: reports/amp-art-380.png (640x860, no key presses, amp view loaded directly).

## Chosen size: 380 px (fits in the two-line case)
Plain 380 did NOT fit with the old spacing: the stack (header 48 -> art -> transport) overflowed by ~10 px for a two-line title, so the header shrank and the art ended 13 px above the grid only because the header text crowded the art. Fit came from three tightenings, no type size changed:
- `.amp-meta` gap 3 -> 0 (-6 px, three lines)
- `.amp-sub` line-height normal (1.5) -> 1.2 (-12.9 px over both sub lines)
- `.amp-transport` padding-top 12 -> 0 (the stack math wasted 12 px above the grid; the grid is bottom-anchored, so it did not move)
`.amp-art` margin-top stays 8. Readings: `margin-top: 6px` (was 36), labels level at 578 / 578.

## Art loading
`/media/img?item=…&w=380`: natural width 380, CSS box 380 (img 378 inside the 1 px border), complete. Server: `imageFor` clamps width to 16-400, so 380 needs no whitelist; no station-specific list. Pre-warm in `playItems` changed 240 -> 380 (160 for lists kept). Station `<img>` also w=380 (not seen live, covered by the updated unit test).

## Tests
tsc clean; 318 passed / 4 skipped (music-screen test now expects w=380).

## Caveats
- Two-line margin is only 0.6 px over the 8 px rule; a bigger header font or a third wrapped line would break it.
- Sub lines at line-height 1.2 rely on overflow:hidden; Hebrew descenders looked fine in the one-line screenshot only.
- Radio view not touched (art/transport rules there unchanged), but `.amp-sub` and `.amp-meta` are amp-only classes.
